# Old Client vs. Group A1 Rules Compatibility Matrix

This document verifies every Firestore operation executed by the **currently published (old) client** against **`docs/rules/A1.rules`** (Group A1 transition rules, deployed **before** the new client rollout in Step 2 of `docs/RULES_RELEASE_GROUPS.md`).

> **Goal**: Zero disruption to existing users, admins, and legacy records while `docs/rules/A1.rules` is active, without weakening self check-in protections (`isActiveMember()`, `sessionOpen`, `tokenValid`, `monthKey`, `isValidCheckInStatus`, `authUid == request.auth.uid`, `checkedInAt == request.time`).

| Currently Published Client Operation | Target Path | Old-Client Payload Characteristics | A1 Verdict | Deciding Rule Line(s) in `docs/rules/A1.rules` |
| :--- | :--- | :--- | :--- | :--- |
| Public leaderboard read | `publicLeaderboard` | Unauthenticated `onSnapshot` collection list | **ALLOW** | `L400`: `allow read: if true;` |
| User initial profile creation (`ensureUserProfile`) | `users/{uid}` | `id == uid`, lowercase Google `email`, `status: 'pending'`, no `memberId`, optional `photoURL` (`https://` or `data:image/`), `notificationPrefs` | **ALLOW** | `L208–L214`: `allow create` + `L129–L156` (`isValidUser`) |
| User self-application / profile edit (`submitApplication`, `requestMembershipLink`, preferences) | `users/{uid}` | Updates `displayName`, `photoURL` (`https://` or `data:image/`), `requestedNotes`, `notificationPreferences` or `notificationPrefs`, `readAnnouncementIds` without mutating `email`/`status`/`memberId` | **ALLOW** | `L216–L230`: `request.resource.data.email == resource.data.email && request.resource.data.status == resource.data.status && affectedKeys().hasOnly([...])` |
| Applicant accept / decline / re-request | `users/{uid}` | `approved_waiting_response -> active/declined`, or `declined/(active && !isActiveMember()) -> pending` | **ALLOW** | `L232–L256`: state transition branches + `L280–L286` (`members/{id}` `authUid` claim) |
| Active member reading roster / sessions / announcements / settings | `members`, `sessions`, `announcements`, `settings` | Authenticated active member `onSnapshot` / `getDoc` | **ALLOW** (Deny pending/declined) | `L270`, `L311`, `L377`, `L417`: `isAdmin() \|\| isActiveMember()` |
| Active member self-profile edit | `members/{memberId}` | Updates `name`, `avatarUrl` (`data:image/` or `https://`), `bio`, `tracks`, `leaderboardOptOut`, `studentId`, `university`, links | **ALLOW** | `L287–L299` + `L158–L174` (`isValidMember` accepts `data:image/.+` and legacy `studentId`/`university`) |
| Admin editing/deactivating/reactivating legacy member | `members/{memberId}` | Document already contains legacy keys (`email`, `phone`, `studentId`, `university`, `department`, `major`, `semester`, counters) | **ALLOW** | `L279`: `isAdmin() && isValidMember(request.resource.data)` (`isValidMember` omits `hasOnly`) |
| Admin creating or editing a legacy session | `sessions/{sessionId}` | May lack `startAt`/`endAt`/`timezone`/`checkInMode`/`openMinutesBefore`/`graceMinutesAfter`/`lateAfterMinutes` or send legacy `status: 'active'` | **ALLOW** | `L312–L316`: `isValidSessionLegacyA1(request.resource.data)` (`L177–L199`) + `affectedKeys().hasOnly(['status','checkInMode','closedAt','updatedAt','cancelledAt'])` |
| Admin updating legacy session status/mode (close/cancel/reopen) | `sessions/{sessionId}` | Updates `status`, `checkInMode`, `closedAt`, `updatedAt`, `cancelledAt` without backfilling `startAt`/`endAt` | **ALLOW** | `L313–L316`: `affectedKeys().hasOnly(['status', 'checkInMode', 'closedAt', 'updatedAt', 'cancelledAt'])` |
| Admin rotating kiosk token (old kiosk client) | `sessionTokens/{sessionId}` | Writes 8-char `token`, empty `prevToken: ''` (or legacy string), `rotatedAt: serverTimestamp()` | **ALLOW** | `L321–L330`: `prevToken` accepts empty/any string; `token` must match `^[A-Z0-9]{8}$` |
| Admin manual door check-in (old client `recordAdminManualCheckIn`) | `checkIns/{sessionId}_{memberId}` | Writes `method: 'manual_entry'`, `authUid`, ISO string `checkedInAt`, denormalized `memberName`/`sessionTitle`/`timestamp`, **omits `verifiedBy`**, may omit or set `monthKey` | **ALLOW** | `L345–L355`: `isAdmin() && method == 'manual_entry' && exists(member) && exists(session) && status in ['present','late'] && (!('verifiedBy' in data) \|\| verifiedBy == auth.uid)` |
| Member self check-in (`recordSelfCheckIn`) | `checkIns/{sessionId}_{memberId}` | `method in ['camera_scan','code_input']`, rotating 8-char `token`, `checkedInAt: serverTimestamp()`, `monthKey`, `authUid == uid` | **ALLOW** (strictly validated; rejects bad tokens/closed/completed sessions) | `L357–L369` + `L60–L70`, `L92–L98` (`sessionOpen` & `isValidCheckInStatus` use `.get()` defaults) |
| Legacy session check-in window & late check (`sessionOpen`, `isValidCheckInStatus`) | `checkIns/{id}` (self check-in) | Session doc has `startAt`/`endAt` but lacks optional `checkInMode`, `openMinutesBefore`, `graceMinutesAfter`, `lateAfterMinutes` | **ALLOW** (evaluates with defaults without crashing) | `L60–L70`, `L92–L98`: `s.get(...)` defaults (`'auto'`, `15`, `30`, `10`) |
| Notification create & owner mark-read on legacy notifications | `notifications/{id}` | Admin or self create with `['id','userId','title','message','createdAt']`; owner toggles `read`/`dismissed` on legacy docs missing `type` or extra keys | **ALLOW** | `L382–L395`: create checks `hasAll` only; owner update checks `affectedKeys().hasOnly(['read','dismissed'])` and immutable `userId` |
| Admin audit log writes (old client `createAuditLog`) | `auditLogs/{logId}` | Old client may write ISO string `timestamp` instead of `serverTimestamp()` | **ALLOW** | `L424–L426`: `isAdmin() && isValidId(logId) && performedBy == request.auth.uid` |
| Public leaderboard point increment by non-admin client (`syncMemberCheckInToPublicLeaderboard`) | `publicLeaderboard/{memberId}` | Best-effort `updateDoc` with `points`/`totalCheckIns`/`monthlyCheckIns` wrapped in `.catch(() => {})` | **DENY** (intentional, non-blocking) | `L403–L413`: only `isAdmin()` can mutate points; member self-sync restricted to display/link keys; stats refreshed by admin backfill/manual sync |

> **Upgrade Note**: Once Step 3 (new client rollout) completes, Step 4 replaces `docs/rules/A1.rules` with `firestore.rules` (`[Group A1 + A2]`), activating strict `serverTimestamp()` and `verifiedBy` checks on manual check-ins, `auditLogs`, `notifications`, and `prevToken`.
